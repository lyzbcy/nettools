# 捞鱼网络工具双平台交付设计

状态：按用户持续执行目标实施；负责人：捞鱼工作室；日期：2026-10-10。

## 目标与现状

将现有 macOS 网络工具升级为 Mac / Windows 同步维护的桌面产品，并接入捞鱼软件中心。现有公开版本 4.4.1；本次拟升至 5.0.0，正式发行以实际验收为前提。

用户已要求遵守 `/Users/zeen/Documents/共享/tools/软件开发` 下的软件规范。软件规范涉及双平台架构、原创素材、图标登记、日志和进度、明显反馈入口、版本和自身更新、项目开发 Skill、软件中心接入以及网页操作的独立观察验收。

已核实缺口：最新公开 ZIP 缺少外层 .app；介绍页仍指向旧版本；Swift 特权助手部分 VPN 参数直接拼入 shell；未装助手时 DNS 回滚可能误报成功；旧更新器缺校验和原应用恢复；软件中心尚未登记本产品。

## 架构选择

推荐：统一 Electron 本地界面和主进程保活状态机，按平台调用系统能力。Mac 复用经过修复的 Swift 执行层，Windows 新增固定动作的系统执行层。用户界面、日志、设置、反馈和更新策略共用。

替代方案一：保留 Mac 原生壳，为 Windows 单独做原生壳。包更小，但保活和升级需维护两份逻辑，容易出现平台行为不一致。

替代方案二：全部用网页加脚本。初次开发简单，但后台定时、权限管理和更新交接不适合作为正式桌面交付。

统一壳保持当前原创表情与暖色主题。渲染进程不开启 Node，使用固定 IPC 白名单；网络修复不接收任意命令或可执行路径。窗口最小化、关闭到托盘时主进程继续计时；用户明确退出时停止守护。开机运行单独选择，不因开启守护而默认添加。

## 保活规则

- 首次安装守护关闭；用户打开后立即检查一次。默认检查间隔 30 分钟，支持 1、5、10、15、30、60 分钟和 1–1440 分钟整数自定义。用户的间隔与开关保存到本机。
- 检查综合链路、地址、路由、DNS、HTTPS 与代理监听结果；单一 ping 失败不能判定断网。公网检查与公司内网检查分开，不将公司内网失败当作整个公网断网。
- 确认公网故障后立即建立一次修复会话，计时从发现故障开始，最长 5 分钟；修复期间的复查频率独立于正常检查间隔。
- 对症修复：DNS 异常刷新缓存；失效的本机代理端口才临时关闭对应代理并保存恢复记录；无地址或默认路由才续租 DHCP。有效代理、静态 IP 和正常 VPN 不随意关闭。每步后复查，恢复后结束本轮。
- 同一时间最多一次检查或修复；单个系统命令有超时和终止保护。修复中切换设置、关闭守护、休眠或恢复后，过期回调不能触发重启。
- 5 分钟仍未恢复：终止本轮修复并记录失败。默认超时动作是“无动作”，保留下一次定期检查；不会重启、关机或断开其他程序。
- 用户可明确开启“修复超时自动重启”，默认关闭，不沿用旧版超级守护状态来开启。开启时说明会关闭应用，可能丢失未保存工作。
- 启用自动重启时，到达 5 分钟后再次检查网络，仍异常才展示可取消的重启提醒；提供 60 秒倒计时，再次恢复或用户取消立即撤销。每次启动最多自动重启一次；自动重启后的启动自动禁用本轮重启策略，防止反复重启。
- 若授权不可用，明确提示无法完成自动修复/重启，不能将权限失败记为成功，也不能持续弹出密码框。

## 权限与系统能力

Mac：修复 Swift helper 的 IP、CIDR、域名和接口校验，禁止参数通过未引用的 shell 展开。对每步结果单独检查，失败就返回错误。DNS 和代理备份保存在私有目录，回滚成功后才显示成功。移除不受校验的旧更新实现与任意调用重启入口；授权升级有明确版本校验。

Windows：提供链路 / DNS / HTTP / 代理检查、WiFi 状态、测速及 DNS / 代理 / DHCP 修复。特权操作使用固定动作与严格类型校验；一次明确授权后才能无人值守执行，授权可卸载。普通启动不默认管理员运行。静态 IP 不自动切到 DHCP。VPN 分流仅在用户配置并验证平台支持后可用，不将未验收功能写作完成。

两平台以各自实际执行结果报告，不返回虚假的绿色成功状态。

## 软件规范落实

1. `SKILL.md` 与 `docs/agent.md` 为接手入口；按模块维护技术、守护、权限、日志、反馈、更新、发布和软件中心适配文档。
2. 日志记录操作名、时间、耗时与分类错误；界面可复制和清空。持久化日志轮转，避免无限增长。敏感值和公司域名/IP不进入默认反馈日志，用户可预览和取消附加日志。
3. 一级“遇到问题反馈”入口；用户主动提交时发送软件名、版本和留言，遵守软件规范指定的反馈通道。机器人凭据不能直接暴露于渲染页面；实际发送需用户提交。
4. 原创星星布丁素材沿用现有飞天图标，核对其他软件并登记真实来源与哈希。Windows 使用主题一致的自绘标题栏和控件。
5. 每日首次自动检查正式新版，日期口径 Asia/Shanghai；分别记录尝试与成功日期，保留手动检查。明确固定仓库、平台/架构资源和 SHA-256。
6. 一键升级先校验下载、再准备替换，等待旧进程退出，保留旧应用，安装验证后可见重启；失败恢复原版和设置。Mac 与 Windows 独立验收。
7. Mac 包包含完整外层 .app，Windows 包主程序固定 `LaoyuNetTools.exe` 且位于 ZIP 根目录；保留许可证与依赖文件。安装器支持路径选择和非系统盘推荐，不强制桌面快捷方式。
8. 稳定产品 ID `nettools`；登记软件中心的目录、平台资源、图标、安装识别和准备规则，严格检查最终包哈希。客户端登记变更必须随新版软件中心发行，不只改远端目录。
9. 介绍页版本、平台、下载和功能边界与已验收发行一致；发布顺序先包后元数据，线上回读核对并保存备份。

## 验收与交付门槛

- 时钟可控的状态机测试覆盖：自定义间隔、正常无修复、故障恢复、5 分钟边界、默认无动作、显式重启、复查恢复、取消、并发、挂起调用、睡眠恢复、重启循环保护。
- 安全测试覆盖：错误 IP/CIDR/域名、命令注入字符、备份恢复失败、授权缺失、错误哈希、降级/同版、重复点击与更新回滚。
- Mac 实际包验证安装、主窗口/托盘、原生只读检查和升级保留数据。真实网络变更在隔离环境验证，不破坏当前用户的工作连接。
- Windows 实际环境验证安装、无白色原生标题栏、可见启动、权限授权与撤销、修复和升级完整链路；在 Mac 上打出 Windows 包不能算 Windows 真机验收。
- 界面回归遵守 tools 中规范，由独立观察 Agent 记录实际操作与预期，并保存报告。
- 包构建、核心逻辑测试、平台实际验收和公开发布分别记录；所有正式交付门槛有证据后才能称正式完成。

当前 Mac 环境已确认；Windows 验收环境等待用户提供或确认。没有真实运行证据时只交付候选包，不标为正式版。
